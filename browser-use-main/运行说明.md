# 运行说明（迁移到新机器 / 给 Agent 看的操作手册）

> 本文件是**自包含**的部署与运行手册，目标读者是「另一台机器上的 AI agent 或人」。
> 按本文从上到下执行即可把项目跑起来。所有路径均相对于本目录 `browser-use-main/`。

---

## 0. 这是什么

一个基于 **vendored（项目内置、已魔改）的 browser-use 库** 的 LLM 浏览器爬虫：
让 Agent 自动在目标网站（主要是 `idp.bl.uk` 等带搜索栏的图库站）搜索关键词、翻页、
批量下载图片 item、提取信息，并把进度持久化到本地 `ImagesCache/` 缓存目录。

主要障碍是目标站的 **Cloudflare Turnstile 人机验证**。本项目已内置应对手段（见第 6 节）。

### 给 Agent 的关键事实（务必先读）

- **操作系统假定 Windows + PowerShell**。Linux/macOS 把反斜杠路径换成正斜杠、`.venv\Scripts\` 换成 `.venv/bin/` 即可。
- **编码坑（必做）**：脚本含中文/emoji，直接 `python xxx.py` 在 Windows 控制台会报 `UnicodeEncodeError`。
  运行任何脚本前先设：`$env:PYTHONIOENCODING='utf-8'`。
- **browser-use 是本地内置的**（`browser_use/` 目录），**不要** `pip install browser-use` 覆盖它。用 `pip install -e .` 安装本地版。
- **不要硬编码绝对路径**。代码里用相对路径（相对脚本位置）。
- **LLM 默认走 SEU 接口**（`https://openapi.seu.edu.cn/v1`，需校园网/VPN）。换 LLM 见第 4 节。
- 反爬的真实 Chrome / 代理配置，三个入口（main / supervisor / GUI）**共用同一组 `IDP_*` 环境变量**，已打通。

## 5. 三种运行入口（选一个）

> 运行前都先：`$env:PYTHONIOENCODING='utf-8'`，并确保已激活 `.venv`。

### 5.1 单次运行 —— `main.py`
跑一轮 Agent（读 `task.md` → 清理 image → 搜索下载 → 重命名）。适合调试。

```powershell
$env:PYTHONIOENCODING='utf-8'; python main.py
```
运行中输入 `quit`+回车 安全停止；`Ctrl+C` 强制中断。

### 5.2 监督循环（推荐）—— `auto_run_until_target.py`
把 `main.py` 当子进程**反复重启**，直到 `ImagesCache/` 达到 `task.md` 里的目标数；
内置断点续跑、自适应冷却（被限流时指数退避）、卡死超时清理。

```powershell
# 续跑：从上次断点继续（同一个关键词接着下）
$env:PYTHONIOENCODING='utf-8'; python auto_run_until_target.py --resume

# 全新开跑某关键词（归档旧缓存，目标 5000 张）
$env:PYTHONIOENCODING='utf-8'; python auto_run_until_target.py --new-run --keyword "china buddhist" --target 5000
```

`--resume` vs `--new-run` 必须二选一：
- `--resume`：第一轮从上次断点页码继续，**不清空**已下载缓存。
- `--new-run`：归档旧 `ImagesCache/` 到存档目录，从头开始。
- 换了 `--keyword` 且与当前不同，会自动归档旧缓存并改写 `task.md`。

常用参数（均有默认，可不填）：

| 参数 | 含义 | 默认 |
|------|------|------|
| `--keyword` | 搜索词（非交互写入 task.md） | 沿用当前 |
| `--target` | 目标下载总数 | 沿用 task.md |
| `--max-rounds` | 最大重启轮数 | 100 |
| `--max-no-progress-rounds` | 连续无新增多少轮后停止 | 3 |
| `--page-delay-seconds` | 每页下载前节流秒数（降 Cloudflare 限流概率） | 12 |
| `--cooldown-seconds` | 无进展时基础冷却秒数（指数递增） | 60 |
| `--round-timeout` | 单轮最长秒数，超时判卡死清理；0=不限 | 0 |

### 5.3 图形界面 —— `run_gui.py`
tkinter 前端，托管上面的 supervisor，实时显示日志/进度，一键停止。
表单里可填：关键词、目标数、LLM key/base_url、并发数、真实 Chrome/代理字段、resume/new-run 模式。

```powershell
$env:PYTHONIOENCODING='utf-8'; python run_gui.py
```
窗口的「Python 解释器」默认就是当前 `sys.executable`，子进程用它来跑。

## 6. 应对 Cloudflare 人机验证（重要）

**原理**：目标站的 Cloudflare Turnstile 主要按「后台浏览器指纹 + IP 信誉」判定，
**不是**靠「点没点中复选框」。所以脚本里模拟点击/视觉点击**解决不了**——闸门不在点击。
真正有效的是：**用一个带真实 cookie / `cf_clearance` 的真实 Chrome profile 出场**，必要时再叠加干净 IP 的代理。

### 启用真实 Chrome profile
三个入口共用同一组环境变量（也可用 CLI 参数 / GUI 字段，最终都写入这些变量）：

| 环境变量 | 含义 |
|----------|------|
| `IDP_CHROME_EXECUTABLE` | 真实 Chrome 可执行文件路径 |
| `IDP_CHROME_USER_DATA_DIR` | Chrome 用户数据目录 |
| `IDP_CHROME_PROFILE_DIRECTORY` | profile 子目录名（默认 `Default`） |

> **必须同时设 `IDP_CHROME_EXECUTABLE` + `IDP_CHROME_USER_DATA_DIR` 且路径存在**，才会启用真实 Chrome；
> 否则自动回退到项目内置 Chromium（不破坏原行为）。

**使用前提（缺一可能失败）：**
1. 先用该 profile **手动**浏览器打开一次目标站、通过验证，让 `cf_clearance` cookie 落到该 profile。
2. 跑之前**完全关闭**那个 Chrome（profile 被占用会启动失败）。
3. 建议**单独建一个 profile 目录**，别用日常 `Default`。

PowerShell 示例：

```powershell
$env:PYTHONIOENCODING='utf-8'
$env:IDP_CHROME_EXECUTABLE   = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
$env:IDP_CHROME_USER_DATA_DIR = 'C:\Users\<你>\bu-chrome-profile'   # 一个专用目录
$env:IDP_CHROME_PROFILE_DIRECTORY = 'Default'
python auto_run_until_target.py --resume
```

或用 CLI 参数（等价）：
```powershell
python auto_run_until_target.py --resume `
  --chrome-executable "C:\Program Files\Google\Chrome\Application\chrome.exe" `
  --chrome-user-data-dir "C:\Users\<你>\bu-chrome-profile"
```

### 可选：叠加代理（攻击 IP 信誉层）
若真实 Chrome 仍被挡，多半是 IP 信誉问题，加住宅代理：

| 环境变量 | 含义 |
|----------|------|
| `IDP_PROXY_SERVER` | 代理地址，如 `http://user:pass@host:port` |
| `IDP_PROXY_BYPASS` | 绕过列表（仅 main.py 支持，GUI/CLI 未暴露） |
| `IDP_PROXY_USERNAME` / `IDP_PROXY_PASSWORD` | 代理账密（也可直接写进 URL） |

```powershell
$env:IDP_PROXY_SERVER = 'http://user:pass@your-proxy:8080'
```
> CLI 对应 `--proxy-server`；GUI 有「代理服务器」输入框。账密直接写进 URL 即可，无需单独设 username/password。

### 还不行的下一档
住宅代理仍被挡 → 考虑 Browser-Use Cloud（`use_cloud=True`，需付费 API key，见 `CLOUD.md`）。

## 6b. 方案C：用 Scrapling 自动取 cf_clearance 通行证（全自动，无需人工点击）

第 6 节的真实 Chrome 方案需要你**手动**开浏览器种一次 `cf_clearance`。方案C 用
**Scrapling**（patchright + browserforge 指纹，能自动通过 Cloudflare Turnstile）
**脚本化批量取证**：自动访问目标站、自动过验证、导出 `cf_clearance` 等 cookie 成
`storage_state` JSON，再由 `main.py` 注入浏览器揣证进站。**supervisor 还会按需自动刷新**
（cookie 缺失/过期、或某轮 0 新增疑似被限流时自动重新取证），全程无需人工干预。

> 已实测：对 `idp.bl.uk` 能自动识别并解决 "managed" 型 Turnstile，取得 `cf_clearance`。

### 工作原理
```
fetch_cf_cookie.py (Scrapling venv) ── 自动过CF ──► cf_storage.json (storage_state)
        ▲ 自动调用                                          │ IDP_STORAGE_STATE
   auto_run_until_target.py（缺失/过期/被限流时触发）        ▼
        └──────────────────────────────► main.py build_browser 注入 → 揣证进站
```

### 一次性准备：装 Scrapling（独立 venv，与 browser-use 隔离）
Scrapling 钉死 `playwright==1.60.0`/`patchright==1.60.1`，**必须单独建 venv**，别装进
browser-use 的 venv（会污染其 cdp-use 栈）：

```powershell
cd <Scrapling 仓库路径>           # 你 clone 的 Scrapling 目录
py -3.14 -m venv .venv            # 任意 3.11+ 均可
.\.venv\Scripts\python.exe -m pip install -e ".[fetchers]"
.\.venv\Scripts\python.exe -m scrapling.cli install        # 装 playwright chromium
.\.venv\Scripts\python.exe -m patchright install chromium  # 装 patchright chromium（StealthySession 用）
```

### 启用方案C
设一个环境变量 `IDP_SCRAPLING_PYTHON` 指向上面的解释器即可（不设则方案C 完全关闭，零影响）：

| 环境变量 | 含义 | 默认 |
|----------|------|------|
| `IDP_SCRAPLING_PYTHON` | Scrapling venv 的 python.exe（设了才启用方案C） | 空=关闭 |
| `IDP_CF_URL` | 取证目标 URL | 目标站首页（`https://idp.bl.uk/`） |
| `IDP_STORAGE_STATE` | cookie 输出/注入路径 | 脚本目录下 `cf_storage.json` |
| `IDP_CF_HEADLESS` | 取证浏览器是否无头（`true`=无窗口，全自动） | `false`（有窗但自动点） |
| `IDP_CF_TIMEOUT_MS` | 取证单步超时毫秒 | `60000` |

```powershell
# supervisor 全自动（推荐）：跑前预取 + 过期/被限流时自动刷新
$env:PYTHONIOENCODING='utf-8'
$env:IDP_SCRAPLING_PYTHON='<Scrapling>\.venv\Scripts\python.exe'
python auto_run_until_target.py --resume
```

GUI 里也有对应三个框（「Scrapling解释器」「取证URL」「cookie文件路径」），其中
Scrapling 解释器会**自动探测**同级 `Scrapling/.venv`，通常无需手填。
CLI 等价参数：`--scrapling-python` / `--cf-url` / `--storage-state`。

### 手动取证 / 调试
```powershell
$env:PYTHONIOENCODING='utf-8'
<Scrapling>\.venv\Scripts\python.exe fetch_cf_cookie.py            # 取默认目标站
<Scrapling>\.venv\Scripts\python.exe fetch_cf_cookie.py https://其他站/
```
退出码：`0`=拿到 cf_clearance；`2`=没拿到（可能本就放行，或 IP 被挡需换代理）；`1`=异常。

### 关键限制（务必理解）
1. **IP 绑定**：`cf_clearance` 与签发它的【出口 IP】绑定。取证（Scrapling）与爬取
   （browser-use）**必须同一出口 IP** —— 都直连，或都设**同一个** `IDP_PROXY_SERVER`
   （见 6c）。本项目已保证两者共用 `IDP_PROXY_*` 环境变量。
2. **会过期**：`cf_clearance` 有寿命，`__cf_bm` 仅约 30 分钟。supervisor 的自动刷新
   （缺失/过期/被限流触发）正是为此设计；新鲜时则秒过不重复启动浏览器。
3. **方案C vs 真实Chrome**：二者本质同源（都给浏览器一张已验证通行证）。方案C 更自动
   （无需人工开浏览器点一下），真实Chrome 更简单（不用装 Scrapling）。可二选一，也可叠加。

## 6c. 住宅代理（Residential Proxy）—— 攻击最深的 IP 信誉层

如果**真实Chrome 和方案C 都仍被挡**，几乎可以断定是 **IP 信誉层**（L1）在拦截：你的
出口 IP（家宽/机房/校园网段）被 Cloudflare 标记为可疑，干净指纹也救不了。这时唯一不
花大钱的解法是换一个**住宅代理**——通过真实家庭宽带 ISP 的 IP 出口，信誉天然干净。

### 为什么必须是"住宅" + "粘性会话"
- **数据中心代理（datacenter）大多无效**：便宜的机房 IP 段同样被 Cloudflare 批量标记。
  要选 **residential** 或 **mobile** 类型。
- **必须粘性（sticky session）**：`cf_clearance` 绑 IP，所以**取证和爬取必须同一个 IP**。
  住宅代理默认每请求轮换 IP（rotating），那样取到的通行证立刻作废。务必用供应商的
  **sticky / session IP** 模式（通常在用户名里编入 session id，保持数十分钟同一 IP）。

### 怎么设
本项目取证与爬取共用同一组代理变量，设一次即可两边生效：

| 环境变量 | 含义 |
|----------|------|
| `IDP_PROXY_SERVER` | 代理地址，如 `http://host:port` 或 `http://user:pass@host:port` |
| `IDP_PROXY_USERNAME` / `IDP_PROXY_PASSWORD` | 账密（也可直接写进上面的 URL） |
| `IDP_PROXY_BYPASS` | 绕过列表（仅 main.py 支持） |

```powershell
# 典型：住宅代理 + 粘性会话（session id 写在用户名里，各供应商语法不同，见其文档）
$env:IDP_PROXY_SERVER = 'http://用户名-session-abc123:密码@gate.供应商.com:7777'
$env:IDP_SCRAPLING_PYTHON = '<Scrapling>\.venv\Scripts\python.exe'
python auto_run_until_target.py --resume
# 此时：fetch_cf_cookie 与 main.py 都走这个代理 → 同一 IP 取证+爬取 → cf_clearance 有效
```

### 选型参考（按性价比/口碑，非广告）
- **入门便宜**：IPRoyal、Webshare（residential）、Proxy-Cheap
- **稳定大厂**：Bright Data、Oxylabs、Smartproxy（Decodo）—— 粘性会话支持完善
- 关注三点：① 是否 **residential/mobile**；② 是否支持 **sticky session ≥10 分钟**；
  ③ 计费按流量（GB）还是按 IP，爬图片走流量要算清成本。

> 顺序建议：先**直连**试方案C（很多站直连就过）→ 不行再上**住宅代理粘性会话** →
> 仍不行才考虑 Browser-Use Cloud（付费，`use_cloud=True`）。

## 8. 故障排查

| 现象 | 处理 |
|------|------|
| `UnicodeEncodeError` / 中文乱码 | 没设 `$env:PYTHONIOENCODING='utf-8'`，补上 |
| 启动报 `未设置 OPENAI_API_KEY` | 设 `OPENAI_API_KEY`（第 4 节） |
| LLM 连接超时 / 403 | 检查校园网/VPN、`OPENAI_BASE_URL`、key 是否正确 |
| 真实 Chrome 启动失败 | 那个 Chrome 没关干净（profile 被占用），全部关掉再跑 |
| 设了 Chrome 路径但仍走内置 Chromium | `IDP_CHROME_EXECUTABLE` 或 `IDP_CHROME_USER_DATA_DIR` 没同时设、或路径不存在（会打印警告回退） |
| 一直被 Cloudflare 挡、0 新增 | ①启用方案C（第6b节）自动取证；②仍不行加住宅代理粘性会话（第6c节） |
| 方案C 取证报"未导入 scrapling" | 用的不是 Scrapling venv 的解释器，检查 `IDP_SCRAPLING_PYTHON` |
| 方案C 每轮都重新开浏览器取证 | 正常仅在 cookie 缺失/过期/被限流时刷新；若频繁，检查 cf_storage.json 是否被外部清空 |
| cf_clearance 取到了爬取仍被挡 | 取证与爬取出口 IP 不一致——确保两边走同一 `IDP_PROXY_SERVER` 且为粘性会话 |
| 下载的图片在哪 | `image/`（单轮）与持久缓存 `ImagesCache/`；旧文件归档到 `history/` |
| 想验证代码不调 LLM | `python test_main.py`（纯功能测试） |

## 10. 最短上手路径（TL;DR）

```powershell
cd <路径>\browser-use-main
python -m venv .venv ; .venv\Scripts\activate
pip install -e .
Copy-Item .env.example .env
$env:PYTHONIOENCODING='utf-8'
$env:OPENAI_API_KEY='你的key'        # 默认 base_url 是 SEU，需校园网；换服务商再设 OPENAI_BASE_URL
python auto_run_until_target.py --new-run --keyword "china buddhist" --target 5000
# 续跑：python auto_run_until_target.py --resume
```
